# Learning Paths

## Purpose

This document explains how the curriculum supports different cybersecurity career directions. Each path describes the phases a learner should prioritize, the skills to build, and the types of evidence that should appear in their portfolio.

**Availability note:** only phases 00–12 currently have course lessons. References to phases 13–19
are future study recommendations, not course content available in this repository. Job roles and
certifications are examples, not promised outcomes.

## Path A: Offensive Security

### Prerequisites

- Phase 01–05 fundamentals
- Comfortable with Linux and networking basics
- Basic scripting skills

### Recommended phases

- Phase 06: Security tools and lab
- Phase 07: Ethical hacking and testing
- Phase 08: Web and API security
- Phase 12: Active Directory and enterprise security
- Phase 14: Advanced penetration testing

### Skills

- Reconnaissance and enumeration
- Exploitation concepts and reporting
- Web and API risk assessment
- Privilege escalation and AD attack paths

### Entry roles

- Junior penetration tester
- Security analyst
- Vulnerability assessment analyst

### Advanced roles

- Senior pentester
- Red team operator
- Security consultant

## Portfolio guidance

No matter which path is chosen, the portfolio should show:

- Written explanations of the security issue and the evidence
- Screenshots, logs, or sanitized artifacts
- Clear remediation choices and risk reasoning
- Documentation that explains the limits of the evidence

A learner should not claim skill solely because a course was completed. Real mastery requires demonstrated evidence, context, and reflection.
