# Curriculum Map

## Overview

This course is designed as a progressive, foundational-to-advanced cybersecurity education path. The primary goal is to help learners understand how systems work, why attackers target them, how defenders respond, and how security can be designed and measured in practice.

The curriculum is intentionally structured to move from fundamentals to applied skills, and then to specialization. It is designed for motivated beginners and intermediate learners who want a practical, evidence-based learning path without pretending that completing a course guarantees job readiness.

**Current implementation:** the repository contains lesson content for phases 00–12. Phases 13–19
below are proposed future curriculum only; their inclusion in this map does not mean they are
available to study.

## Phase structure

| Phase | Focus | Outcomes |
| --- | --- | --- |
| 00 | Introduction and context | Security framing, risk mindset, roles, and case-based understanding |
| 01 | Computer fundamentals | Hardware, operating systems, virtualization, internet basics |
| 02 | Networking | IP, protocols, routing, network security, and tools |
| 03 | Operating systems | Linux, Windows, administration, identities, and system basics |
| 04 | Programming and scripting | Python, Bash, PowerShell, SQL, JavaScript, Go, and automation |
| 05 | Cybersecurity fundamentals | Principles, cryptography, identity, frameworks, and risk |
| 06 | Security tools and labs | Safe lab environment, packet analysis, scanning, and tooling |
| 07 | Ethical hacking and testing | Reconnaissance, web testing, exploitation concepts, reporting |
| 08 | Web and API security | App architecture, OWASP, APIs, and secure design |
| 09 | Network and system security | Hardening, segmentation, resilience, and controls |
| 10 | Defensive security and SOC | Monitoring, triage, alerts, detection, and incident response |
| 11 | Forensics and malware analysis | Evidence handling, malware basics, memory and behavior analysis |
| 12 | Active Directory and enterprise security | Identity, privilege, enterprise controls, and monitoring |
| 13 | Cloud security engineering | AWS/Azure/GCP, IAM, logging, IaC, and cloud defense |
| 14 | Advanced penetration testing | Internal targeting, AD attack paths, pivoting, and reporting |
| 15 | Malware analysis and reverse engineering | Assembly, PE, behavior, YARA, and methodologies |
| 16 | Application security engineering | SDLC, secure coding, SAST/DAST, SBOM, and DevSecOps |
| 17 | Wireless and mobile security | Wi-Fi, mobile app security, OWASP MASVS/MASTG, and testing |
| 18 | Advanced SOC and detection engineering | SIEM, hunting, Sigma, threat intel, and automation |
| 19 | Security architecture and engineering | Zero Trust, governance, design reviews, and enterprise security |

## Learning progression model

Each phase should support a consistent learning model:

- Learn the concept
- Practice with controlled examples
- Apply in a safe lab
- Explain evidence and limitations
- Document findings
- Assess understanding

## Assessment model

A consistent rubric should be used across all phases:

- Conceptual understanding: 20%
- Technical implementation: 25%
- Practical problem solving: 25%
- Evidence and documentation: 15%
- Security reasoning and remediation: 15%

Recommended pass threshold: 80%.

The site now applies a short knowledge check and a practical evidence rubric to each current phase.
The practical score and prerequisite check are self-assessed in the learner's browser; they are not
independently verified and do not establish professional competency.

## Required assessment components per phase

1. Prerequisite assessment
2. Knowledge assessment
3. Practical lab examination
4. Independent challenge
5. Final phase examination
6. Portfolio submission
7. Revision checklist

## Professional pathway coverage

The curriculum supports multiple specialization tracks:

- Offensive Security
- Cloud Security Engineering
- SOC and Blue Team
- Application Security
- Malware Analysis and Digital Forensics

## Quality expectations

Assessments should verify actual understanding rather than lesson completion alone. A learner should demonstrate that they can explain, apply, and document security work in context with appropriate risk boundaries.

## Implementation note

This curriculum map is intended to guide future phase design and quality reviews. It should be used with the learning pathways and resource index to ensure that each phase remains aligned to practical mastery and professional relevance.
