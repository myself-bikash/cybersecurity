# Assembly Language

## Learning objectives

By the end of this lesson, you should be able to:

- Explain the relationship between Assembly and processor instructions.
- Identify the Assembly topics and security applications listed in the source.
- Describe when the source recommends studying Assembly.

## What is Assembly?

Assembly is a low-level programming language closely related to processor instructions. The
source says it helps learners understand what a computer executes.

## Assembly syllabus

1. Binary and hexadecimal.
2. CPU registers.
3. Processor architecture.
4. Assembly instructions.
5. Memory addressing.
6. Stack operations.
7. Function calls.
8. Conditional jumps.
9. Loops.
10. System calls.
11. Machine code.
12. Disassembly.
13. Debugging.
14. x86 and x86-64 architecture.

## Cybersecurity applications and learning stage

The source lists reverse engineering, malware analysis, binary analysis, understanding exploit
development, and analyzing executable files. It says learners do not need to master Assembly at
this stage and recommends learning it when they reach reverse engineering and binary exploitation.

This lesson introduces these areas without procedures for exploitation or malware execution.

## Practical lab: instruction concepts

Use a paper worksheet or instructor-provided, non-executable example:

1. Match binary/hexadecimal, registers, memory addressing, stack operations, and instructions to
   their place in the syllabus.
2. Explain the difference between machine code and disassembly at a high level.
3. Identify which topics relate to processor architecture.

Do not execute unknown binaries or analyze malware outside a properly isolated, authorized lab.

## Key takeaways

- Assembly is closely related to processor instructions.
- The source covers architecture, registers, memory, control flow, calls, system calls, machine
  code, disassembly, and debugging.
- The source recommends studying Assembly later, alongside reverse engineering and binary
  analysis.
