# Phase 7: Final Revision and Assessment

## Learning objectives

- Recall the authorized-testing definitions from the phase.
- Compare commonly confused security concepts.
- Assess your understanding with the source's 30 questions and 27-item checklist.
- Keep all practical work within written authorization and a safe training boundary.

## Important definitions

| Term | Simple definition |
| --- | --- |
| Ethical hacking | Authorized security testing. |
| Penetration testing | Controlled testing to validate security weaknesses. |
| Scope | Systems and activities permitted for testing. |
| Rules of engagement | Instructions governing a test. |
| Reconnaissance | Collecting target information. |
| OSINT | Intelligence from publicly available sources. |
| DNS enumeration | Collecting DNS-related information. |
| Scanning | Examining systems and services. |
| Enumeration | Collecting detailed service information. |
| Vulnerability | A security weakness. |
| CVE | Identifier for a publicly disclosed vulnerability. |
| CVSS | Vulnerability severity-scoring framework. |
| Exploit | Technique that takes advantage of a vulnerability. |
| PoC | Demonstration that a vulnerability exists or has an effect. |
| Payload | Component intended to perform an action after a weakness is triggered. |
| RCE | Remote code execution. |
| Privilege escalation | Gaining higher permissions than intended. |
| Session hijacking | Unauthorized use of another user's session. |
| Remediation | Fixing or reducing a security weakness. |
| Retesting | Checking whether a fix works. |

## Important comparisons

| Comparison | Main difference |
| --- | --- |
| Passive vs. active reconnaissance | Public-information collection vs. direct interaction with target infrastructure. |
| Vulnerability assessment vs. penetration testing | Identifying weaknesses vs. validating selected weaknesses. |
| CVE vs. CVSS | Vulnerability identifier vs. severity scoring system. |
| Authentication vs. authorization | Identity verification vs. permission checking. |
| Vertical vs. horizontal escalation | Higher privileges vs. another user's resources. |
| Vulnerability vs. exploit | Weakness vs. method of taking advantage of it. |
| PoC vs. payload | Demonstration vs. action performed by exploit code. |
| Remediation vs. retesting | Fixing the issue vs. verifying the fix. |

## Practical review

Use the fictional SecureTech case or sanitized sample evidence. Create a short report containing
scope, one evidence-backed finding, severity reasoning, remediation, retest status, and limitations.
Do not perform active testing.

## Key takeaways

- Authorization, scope, and safe boundaries apply throughout every testing stage.
- Vulnerabilities, identifiers, scores, exploits, and PoCs are distinct concepts.
- Evidence, business impact, remediation, and retesting make findings useful.
- A high quiz score does not replace safe practical judgment.

2. What evidence would you need before prioritizing a real vulnerability?
