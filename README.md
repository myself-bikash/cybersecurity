The course is organized as a sequence of short, linked lessons, safe exercises, phase projects, and
revision pages. Each step aims to turn a concept into something you can explain, demonstrate in an
authorized lab, or document clearly. You do not need to memorize every tool or command to make
progress.

## What you'll build

- **A mental model:** understand computers, networks, operating systems, identities, and security
  controls before relying on tools.
- **Practical judgment:** choose a safe next step, interpret evidence in context, and know when a
  conclusion is uncertain.
- **A learning portfolio:** save diagrams, risk assessments, lab notes, detections, and reports
  using fictional or sanitized data.
- **A connected view of security:** relate prevention, monitoring, response, and recovery instead
  of treating them as unrelated topics.

## A simple rhythm for every lesson

**Preview → understand → try → explain → reflect.** Read the objectives, study the examples, do
the smallest safe exercise that tests the idea, explain what the evidence does and does not show,
then use the revision questions to find what to revisit.

Work on the [cumulative capstone](capstone/index.md) as you progress, or complete each phase
independently. The capstone uses a fictional company and synthetic evidence; it never requires
access to a real organization's systems.

## Safety is part of the skill

Only assess systems, accounts, and data that you own or are explicitly authorized to use. Keep
training systems isolated when a lesson calls for a lab. Do not treat public accessibility as
permission. Many exercises can be completed using supplied examples or synthetic data without
running security tools.
