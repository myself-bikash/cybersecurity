# Networking Practical Projects

## Learning objectives

By the end of these projects, you should be able to:

- Apply Phase 2 concepts in an owned or isolated training network.
- Capture and interpret authorized lab traffic.
- Describe a TCP handshake and DNS exchange from permitted training data.
- Document network-discovery work without testing third-party systems.

## Authorization and lab boundaries

The source explicitly limits Nmap scanning to your own lab network and states that tools should be
used on systems you own or have permission to test. Keep the projects within an isolated virtual
network or another environment whose scope you control. Do not scan public IPs, school/work
networks, neighbors' devices, or any third party without explicit authorization.

## Project 1: capture network packets

Capture traffic generated by your own lab devices on an isolated network and identify different
protocols. Use a training capture if live capture is not appropriate. Do not capture other users'
traffic; record only information needed for the exercise.

## Project 2: analyze a TCP handshake

Using permitted training traffic, find the SYN, SYN-ACK, and ACK packets in Wireshark and explain
the order described in the Network Security lesson.

## Project 3: identify DNS requests

Generate or use an authorized training exchange and identify DNS queries and responses. Do not
inspect another person's traffic.

## Project 4: scan your own lab network with Nmap

Discover devices, open ports, and running services only on your own isolated lab network or systems
for which you have explicit permission. Record the approved scope and summarize the findings. This
project intentionally does not provide a command sequence or instructions for scanning third-party
systems.

## Project 5: create a virtual network

Connect two virtual machines in an isolated virtual network and test communication between those
VMs. Document the network diagram and the permitted scope.

## Progress checklist

- [ ] Captured network packets in an authorized environment.
- [ ] Identified different protocols in the capture.
- [ ] Located SYN, SYN-ACK, and ACK in permitted training data.
- [ ] Identified DNS queries and responses.
- [ ] Scanned only an owned or explicitly authorized lab network.
- [ ] Connected two virtual machines and tested their communication.

## Recommended learning order

The source suggests the following study plan:

| Module / activity | Suggested time |
| --- | --- |
| Networking basics | 2 days |
| OSI model | 1 day |
| TCP/IP model | 1 day |
| IP addressing and subnetting | 3 days |
| Network protocols | 2 days |
| Network security | 3 days |
| Networking tools | 3 days |
| Practical projects and revision | 3 days |
| **Total** | **18 days** |

## Key takeaways

- Practical work should reinforce the concepts from the seven modules.
- Packet capture, DNS inspection, and network discovery can expose sensitive information and must
  stay within an authorized lab.
- The source's study plan totals 18 days.
